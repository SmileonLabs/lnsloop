# LNS Pulse PoC 접근성·개인정보·모션 QA 체크리스트

- 문서 상태: PoC 출시 전 기준
- 최종 갱신: 2026-09-07
- 적용 대상: LNS Pulse 모바일 앱의 가입, 건강 기록, 연구 참여, 동의, 활동 수행, LNS 보상 확인 흐름
- 적용 환경: iOS 및 Android

## 1. 목적

이 문서는 LNS Pulse의 모션이 사용자의 이해를 돕는 상태 피드백으로만 작동하고, 다음 문제를 만들지 않는지 출시 전에 확인하기 위한 체크리스트다.

- 움직임에 민감한 사용자가 핵심 기능을 이용하지 못하는 문제
- 모션으로 인한 프레임 저하, 발열, 배터리 소모
- 진단, 치료 효과 또는 의료진 검증으로 오해할 수 있는 표현
- 앱 전환기, 잠금화면, 화면 공유 및 분석 도구를 통한 개인정보 노출
- LNS 보상이 연구 참여를 과도하게 유도하거나 투기적으로 보이는 문제
- 화면의 성공 표현과 서버·블록체인의 실제 상태가 다른 문제

PoC의 기본 원칙은 다음과 같다.

> 모션은 건강이 좋아지고 있거나 돈을 벌고 있다는 인상을 주는 장식이 아니라, 사용자의 행동이 접수·처리·검증됐다는 사실을 조용히 알려주는 피드백이어야 한다.

| P3 | 경미한 시각적 완성도 문제 | 일부 easing 불일치 | 후속 개선 가능 |

## 3. PoC 첫 구현 범위

### 3.1 포함하는 모션

| 사용처 | 기본 표현 | 시간 기준 | Reduced Motion 대체 |
| --- | --- | --- | --- |
| 버튼·카드 탭 | 가벼운 투명도 또는 눌림 변화 | 80~120ms | 색·테두리 상태 즉시 변경 |
| 화면 전환 | 짧은 페이드 또는 8~12px 이내 단축 이동 | 180~220ms | 100ms 이하 페이드 또는 즉시 전환 |
| 바텀시트·대화상자 | 배경 페이드와 짧은 상승 | 220~280ms | 배경 페이드 또는 즉시 표시 |
| 저장·동기화 | 상태 라벨과 단일 진행 표시 | 처리 중에만 | 정적 아이콘과 상태 라벨 |
| 활동 완료 | 체크 아이콘 페이드 | 약 200ms | 체크 아이콘 즉시 표시 |
| LNS 지급 완료 | 체크 표시 후 금액 한 번 갱신 | 300ms 이내 | 최종 금액 즉시 표시 |
| 오류 | 정적 오류 아이콘, 설명, 재시도 버튼 | 장식 모션 없음 | 동일 |

### 3.2 PoC에서 제외하는 모션

- 홈 화면의 무한 루프, 자동 재생 배경 및 호흡하듯 반복되는 카드
- 패럴랙스, 3D 회전, 깊이 변화, 강한 블러 전환, 화면 전체 줌
- 스프링 overshoot, bounce, 고무줄처럼 늘어나는 전환
- 파티클, 코인 비, 폭죽, 슬롯머신, 룰렛, 보물상자
- 실시간 토큰 시세 티커, 가격 상승 화살표 및 수익률 카운트업
- 스트릭, 순위표, 추천인 경쟁 및 놓치면 손해라는 카운트다운
- 실제 센서 입력과 무관한 심전도, 맥박, 산소포화도 또는 생체 파형
- AI가 건강 상태를 검사하거나 진단하는 것처럼 보이는 스캔 효과
- 건강 점수의 상승을 회복이나 치료 효과처럼 보이게 하는 연출
- 건강 데이터가 코인이나 지갑으로 흘러 들어가는 연출
- 애니메이션 기반 차트 전환 및 자동 재생 데이터 스토리

## 4. 접근성 체크리스트

### 4.1 정보 전달

- [ ] 성공, 실패, 경고, 검증 상태를 모션만으로 전달하지 않는다.
- [ ] 색상, 진동 또는 소리만으로 중요한 상태를 구분하지 않는다.
- [ ] 아이콘에는 보이는 텍스트 또는 접근성 레이블이 있다.
- [ ] 상태가 바뀌어도 기존 텍스트를 읽을 충분한 시간이 보장된다.
- [ ] 자동으로 사라지는 메시지는 핵심 정보를 포함하지 않거나 다시 확인할 수 있다.
- [ ] 움직임이 없어도 처리 중, 검증 대기, 지급 완료를 구분할 수 있다.
- [ ] 진행 시간을 알 수 있을 때는 determinate progress를 사용하고, 모를 때는 텍스트로 상태를 함께 표시한다.

### 4.2 스크린리더·포커스

- [ ] VoiceOver와 TalkBack의 읽기 순서가 시각적 순서와 일치한다.
- [ ] 화면 전환 후 포커스가 화면 제목 또는 첫 핵심 요소로 이동한다.
- [ ] 바텀시트가 열리면 포커스가 그 안에 머물고, 닫히면 호출한 요소로 돌아간다.
- [ ] 로딩 상태는 반복 낭독하지 않고 시작과 완료를 필요한 횟수만 안내한다.
- [ ] 금액 카운트업 중 중간 숫자를 반복 낭독하지 않고 최종 금액만 안내한다.
- [ ] 오류 발생 시 오류 요약과 해결 행동이 연속해서 읽힌다.
- [ ] 동의 체크박스, 서명, 철회 버튼의 선택 상태와 결과가 정확히 읽힌다.
- [ ] 화면 애니메이션 중에도 접근성 트리가 중복되거나 사라지지 않는다.

### 4.3 글자·색상·조작

- [ ] 글자 크기 200% 이상에서 필수 텍스트와 버튼이 잘리지 않는다.
- [ ] 확대 글자에서 중요 버튼이 화면 밖으로 밀리거나 모션 뒤에 가려지지 않는다.
- [ ] 일반 텍스트 명암비 4.5:1, 큰 텍스트 3:1 이상을 충족한다.
- [ ] 아이콘, 입력 테두리 및 포커스 표시의 비텍스트 명암비가 3:1 이상이다.
- [ ] 상태를 빨강·초록 색상만으로 구분하지 않는다.
- [ ] 터치 영역은 iOS 44x44pt, Android 48x48dp 이상이다.
- [ ] 드래그가 필요한 기능은 탭 방식의 대안이 있다.
- [ ] 스위치 제어, Voice Control 및 외부 키보드로 핵심 흐름을 수행할 수 있다.

## 5. Reduced Motion 체크리스트

- [ ] iOS의 Reduce Motion 설정을 앱 시작과 설정 변경 시 모두 감지한다.
- [ ] Android의 애니메이션 제거 또는 animator duration scale 설정을 반영한다.
- [ ] 앱 안에 별도의 `움직임 줄이기` 설정을 제공하고 시스템 설정을 기본값으로 따른다.
- [ ] Reduced Motion을 켜도 탐색 구조, 정보량 및 완료 가능한 기능이 줄어들지 않는다.
- [ ] 큰 축 이동, 줌, 회전, 패럴랙스 및 반복 모션을 페이드 또는 즉시 전환으로 교체한다.
- [ ] 감소 모드의 페이드는 100ms 이하이며 필수 읽기 시간을 줄이지 않는다.
- [ ] 앱 사용 중 설정이 바뀌면 재시작 없이 다음 모션부터 반영한다.
- [ ] 네트워크 로딩은 모션 제거 후에도 멈춘 화면처럼 보이지 않도록 상태 문구를 유지한다.
- [ ] 애니메이션을 건너뛰어도 이벤트, 저장, 검증 또는 지급 로직은 동일하게 실행된다.
- [ ] 제3자 애니메이션 자산도 Reduced Motion 설정을 따른다.
- [ ] 1초당 3회를 초과하는 점멸이 없다.
- [ ] 필수 진행 표시를 제외하고 5초 이상 자동으로 움직이는 요소가 없다.

## 6. 프레임·배터리·성능 체크리스트

### 6.1 구현 기준

- [ ] 위치·크기·여백의 매 프레임 재계산보다 opacity와 transform을 우선한다.
- [ ] 한 화면에서 동시에 실행되는 지속 모션은 최대 1개다.
- [ ] 완료·보상 모션은 1회만 실행하고 2초 안에 끝난다.
- [ ] 화면 밖, 다른 탭, 잠금 상태 및 백그라운드에서는 모션 타이머를 중지한다.
- [ ] 모션 타이머가 네트워크 폴링, 의료 데이터 동기화 또는 가격 조회를 직접 발생시키지 않는다.
- [ ] 긴 작업은 UI 스레드에서 실행하지 않는다.
- [ ] 대용량 이미지, 블러, 그림자 및 벡터 애니메이션을 동시에 중첩하지 않는다.
- [ ] 로딩 실패 상태에서 스피너가 무한히 남지 않고 오류·재시도 상태로 전환된다.
- [ ] 저전력 모드에서는 장식 모션을 제거하고 업데이트 빈도를 낮춘다.

### 6.2 측정 기준

- [ ] 핵심 시나리오에서 측정 프레임의 95% 이상이 16.7ms 이내에 렌더링된다.
- [ ] Android 기준 700ms 이상의 frozen frame이 0건이다.
- [ ] 화면 전환 중 입력이 100ms 이상 불필요하게 차단되지 않는다.
- [ ] 15분 반복 시나리오에서 모션 적용 버전의 에너지 사용량이 정적 기준 대비 10% 이상 증가하지 않는다.
- [ ] 화면을 끄거나 앱을 백그라운드에 둔 뒤 모션 관련 wake-up이 0건이다.
- [ ] 동일 화면을 20회 왕복한 뒤 지속적으로 증가하는 메모리 사용량이 없다.
- [ ] 저사양 기준 기기에서 발열 또는 thermal throttling으로 모션이 급격히 느려지지 않는다.
- [ ] 콜드 스타트 애니메이션이 첫 입력 가능 시점을 지연하지 않는다.

측정은 릴리스 빌드에서 수행한다. 개발 모드 수치는 출시 판단에 사용하지 않는다.

## 7. 앱 전환기·화면 캡처 개인정보 체크리스트

- [ ] 앱이 비활성화되거나 백그라운드로 가기 전에 민감 화면에 중립 커버를 표시한다.
- [ ] iOS 앱 전환기 스냅샷에 진단명, 증상값, 연구명, 보상액, 지갑 잔액 및 지갑주소가 남지 않는다.
- [ ] Android 최근 앱 화면에 같은 정보가 노출되지 않는다.
- [ ] 앱 복귀 시 생체인증 정책에 따라 민감정보를 다시 표시한다.
- [ ] 커버를 적용하거나 해제할 때 이전 민감 화면이 전환 프레임 사이로 보이지 않는다.
- [ ] 건강 기록 상세, 신원정보, 복구정보 및 지갑 상세 화면은 캡처·미러링 정책을 적용한다.
- [ ] Android의 민감 화면에는 `FLAG_SECURE` 적용 필요성을 화면별로 검토한다.
- [ ] iOS 화면 녹화·미러링 감지 시 민감정보를 가리거나 사용자에게 명확히 알린다.
- [ ] 화면 캡처 제한이 고객지원이나 자신의 기록 보관을 불필요하게 막지 않도록 화면별 정책과 대체 내보내기 기능을 정의한다.
- [ ] 잔액과 보상 내역에 사용자가 선택할 수 있는 숨김 모드가 있다.
- [ ] 앱 전환기 커버 자체에 질환이나 암호화폐 사용을 추정할 수 있는 문구가 없다.

## 8. 알림 개인정보·유도 체크리스트

### 8.1 기본 문구

- [ ] 잠금화면 기본 알림에는 질환명, 증상명, 병원명, 연구명, 의료진명, LNS 수량 및 환산 금액을 넣지 않는다.
- [ ] 기본 문구는 `확인할 활동이 있어요`, `앱에서 진행 상태를 확인해 주세요`처럼 중립적으로 작성한다.
- [ ] 사용자가 명시적으로 선택한 경우에만 상세 알림을 허용한다.
- [ ] Android 알림의 visibility를 private 또는 secret으로 설정한다.
- [ ] 알림 딥링크 진입 시 인증 전에는 민감 화면이나 내용을 표시하지 않는다.
- [ ] 로그아웃·세션 만료 사용자의 알림 미리보기에 이전 사용자 정보가 남지 않는다.

### 8.2 빈도와 표현

- [ ] 연구 참여 전 알림 권한을 먼저 강요하지 않는다.
- [ ] 건강 기록 누락을 비난하거나 불안을 높이는 표현을 사용하지 않는다.
- [ ] `마감 임박`, `보상을 잃습니다`, `지금 참여` 같은 FOMO 문구를 사용하지 않는다.
- [ ] 동일 활동 알림을 중복 전송하지 않는다.
- [ ] 사용자가 빈도, 조용한 시간, 연구별 알림을 제어할 수 있다.
- [ ] 긴급 의료 알림처럼 보이는 사운드나 `time-sensitive` 속성을 일반 연구 활동에 사용하지 않는다.
- [ ] LNS 지급 실패는 상세 자산 정보를 노출하지 않고 앱 내 확인을 유도한다.

## 9. 의료적 오해 방지 체크리스트

- [ ] `저장됨`, `전송됨`, `검증 대기`, `검증 완료`를 `정상`, `안전`, `회복`, `치료됨`과 구분한다.
- [ ] 사용자가 직접 입력한 정보에는 `직접 기록`, 의료기관 자료에는 `기관 자료`, 연구 검증을 거친 항목에는 `검증 완료`를 표시한다.
- [ ] 데이터 업로드 성공을 의료진 검토 완료처럼 표현하지 않는다.
- [ ] 실제 센서 연결이 없으면 맥박·심전도·산소포화도와 유사한 실시간 파형을 사용하지 않는다.
- [ ] `AI 분석 중` 또는 `건강 스캔 중`처럼 진단 기능을 암시하는 모션을 사용하지 않는다.
- [ ] 건강 추세 애니메이션이 인과관계, 치료 효과 또는 예후를 암시하지 않는다.
- [ ] 위험·주의·정상 상태를 색이나 모션만으로 결정하지 않는다.
- [ ] 사용자 입력과 의학적 판정의 차이를 화면 문구로 설명한다.
- [ ] 심각한 증상 응답에는 정적 안내 문구와 명확한 다음 행동을 제공한다.
- [ ] 긴급 상황에서 앱이나 연구팀이 응급의료를 대신한다는 인상을 주지 않는다.
- [ ] 의료 콘텐츠 책임자가 환자에게 보이는 모든 상태명, 아이콘, 모션 및 오류 문구를 검토한다.
- [ ] 연구 동의 화면의 위험·부담 설명 중에는 자동 모션이나 보상 축하 효과를 사용하지 않는다.

## 10. LNS 보상 윤리·정확성 체크리스트

### 10.1 윤리적 표현

- [ ] 보상은 질병, 데이터의 희소성 또는 중증도가 아니라 시간과 활동 부담을 기준으로 표시한다.
- [ ] 연구 목적, 필요한 활동, 데이터 범위, 위험·불편 및 철회 방법을 보상과 같거나 더 높은 시각적 우선순위로 표시한다.
- [ ] 동의 전 보상액을 과도하게 확대·반짝임·진동으로 강조하지 않는다.
- [ ] 가입, 질환 보유 자체, 추천인 수 또는 데이터 양에 대한 투기적 보상을 제공하지 않는다.
- [ ] 랜덤 보상, loot box, streak, 순위표, 손실 회피 및 제한시간 연출을 사용하지 않는다.
- [ ] 토큰 가격 상승, 수익률, 투자 기회, 상장 기대를 암시하지 않는다.
- [ ] 중도 철회해도 이미 완료·검증된 활동의 보상을 회수하지 않는다.
- [ ] 미완료 활동 때문에 기존 보상이 줄어드는 것처럼 표현하지 않는다.
- [ ] HREC/IRB 검토 자료에 실제 보상 화면, 알림 문구, 모션 영상 및 Reduced Motion 버전을 포함한다.

### 10.2 금액과 지급 상태

- [ ] 예상 보상, 검증 대기, 지급 확정 및 출금 가능 상태를 명확히 분리한다.
- [ ] 법정화폐 기준 가치, LNS 환산 기준 시각, 적용 가격, 수수료 및 변동성 안내가 정적으로 제공된다.
- [ ] 카운트업 애니메이션과 무관하게 최종 금액을 즉시 읽고 복사할 수 있다.
- [ ] 서버 승인과 온체인 확정 전에는 지급 완료 모션을 실행하지 않는다.
- [ ] pending 상태를 잔액에 확정 자산처럼 합산하지 않는다.
- [ ] 실패·만료·재시도 상태에서 성공 색상과 축하 모션이 남지 않는다.
- [ ] 빠른 연속 탭, 재시작 및 네트워크 재연결로 중복 지급 요청이 만들어지지 않는다.
- [ ] 보상 원장, 지급 요청, 온체인 거래 ID 및 사용자 표시 금액이 일치한다.
- [ ] 실패한 지급을 운영자가 재처리할 때 멱등성이 유지된다.
- [ ] 접근성 알림은 중간 금액이 아니라 확정된 결과를 한 번만 읽는다.

## 11. 로깅·분석·세션 리플레이 체크리스트

- [ ] 이벤트명과 속성에 질환명, 증상값, 검사 결과, 연구 참여 여부, 병원명, 지갑주소 및 보상액을 넣지 않는다.
- [ ] 화면 제목 자체가 민감정보인 경우 분석 이벤트에서 일반화된 화면 식별자를 사용한다.
- [ ] 네트워크 요청·오류 로그에 동의서 본문과 의료정보가 포함되지 않는다.
- [ ] 스크린샷 기반 크래시 리포트와 세션 리플레이를 비활성화한다.
- [ ] 외부 모션·분석 SDK가 화면 내용, 터치 위치 또는 식별자를 수집하지 않는지 확인한다.
- [ ] 로그에서 사용자 ID와 지갑주소를 직접 연결하지 않는다.
- [ ] QA 로그와 테스트 fixture는 실제 환자·실제 지갑 데이터를 사용하지 않는다.
- [ ] 운영 디버그 모드를 원격으로 켜더라도 민감정보가 추가 수집되지 않는다.
