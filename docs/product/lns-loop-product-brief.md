# LNS Loop 제품 기준안

기준일: 2026-09-11 · 출처: [SmileOn Labs 제공 원문](../reference/2026-09-11-smileon-labs-original.txt)

이 문서는 사용자가 제공한 추천안과 개발 방향을 정리한 제품 기준이다. 현재 구현 완료 명세나 연구·법률 승인 결과를 뜻하지 않는다. 원문의 보상액은 가설, 일정과 KPI는 목표이며 외부 기관 관련 설명은 별도로 검증하지 않았다.

## 후속 변경: 현재 초기 앱 범위

2026-09-11 후속 사용자 지시로 **소개 온보딩 보류, Google 로그인, 포인트 적립 우선**으로 변경했다. [초기 앱 기능 정리](lns-loop-mvp-features.md)를 현재 가입·보상·화면 구성의 기준으로 읽는다. 아래 최초 추천안의 이메일·패스키 가입, A$100 LNS 보상, 지갑·테스트넷·메인넷 지급 및 관련 일정은 과거 제안으로 보관하며 이번 초기 구현에 적용하지 않는다. 활동별 포인트 점수는 미정이다. 사용자 화면에는 포인트만 표시하며 에어드랍·토큰 전환·향후 배분 예고 문구를 넣지 않는다.

추가 화면 결정: Google 로그인, LNS 프로젝트 소개 Index, 연구 설명 → 동의 → 적합성 확인, 포인트 지급, 총 포인트·랭킹, 마이페이지. **랭킹은 후속 사용자 지시로 포함**하며 아래 최초 추천안의 리더보드 제외 항목보다 우선한다.

## 1. 제품 방향

> 작은 기록이 더 나은 연구로 이어져요.

참여자가 연구를 이해하고, 출처를 확인할 수 있는 건강기록을 연결하고, 12주 동안 부담 없이 참여하며 완료한 기여에 정확하게 보상받는 경험을 먼저 완성한다. 다운로드 수나 LNS 거래량을 성공 기준으로 삼지 않는다.

| 항목 | 기준안 |
| --- | --- |
| 가칭 | LNS Loop |
| 첫 참여 지역 | 호주 빅토리아주·멜버른 |
| 첫 구매 고객 | 미국·글로벌 제약사, 바이오텍, CRO |
| 첫 대상 질환 | 성인 궤양성 대장염(UC) |
| 첫 연구 | 100명, 12주 비중재 관찰 연구 |
| 플랫폼·언어 | iOS·Android 동시 개발, 영어 우선 |
| 수집 범위 | 병원기록 + 기존 검사결과 + 짧은 증상 기록 |
| 보상 | 완료한 기여 활동별 LNS 단계 지급 |
| 의료정보 저장 | 호주 리전 암호화 서버 |
| 블록체인 역할 | 보상 지급 및 감사 증명 |
| 핵심 KPI | 검증된 참여자-주(Verified Participant-Weeks) |

호주 선정 배경은 영어권, 임상연구 기반, My Health Record의 소비자 앱용 FHIR 연결 가능성이다. 실제 연결에는 등록·심사와 의료기관 협력이 필요하다는 것이 원문의 전제다. UC는 일상 증상과 병원 정보를 결합해 치료 변경 전후의 생활 변화를 연구하기 적합하다는 취지로 선정했다.

## 2. 첫 연구: UC Life Study

가칭: **UC Life Study – 12주 동안 내 치료와 일상의 변화 알아보기**

1. 본인 확인 및 연구 설명 확인
2. 동의 항목별 선택
3. 병원기록 연결 또는 문서 업로드
4. 복용 중인 약 확인
5. 매주 60~90초 증상 체크
6. 월 1회 생활 상태 설문
7. 연구 종료 후 결과 요약 확인
8. 완료한 활동만큼 LNS 보상 수령

첫 연구는 새 약 투여나 치료 권고를 하지 않는다. 새로운 혈액·타액·대변 검체도 제외하고 기존 병원기록과 일상 기록의 결합부터 검증한다.

### 데이터 항목

| 출처 | 항목 |
| --- | --- |
| 참여자 기록 | 하루 배변 횟수, 혈변 여부, 배변 긴급성, 복통·피로, 복약 여부, 일상생활 영향 |
| 병원 정보 | 진단명·진단 시점, 현재·과거 약물, 치료 변경, 입원·검사 이력, 기존 CRP·분변 칼프로텍틴 결과, 필요한 경우 내시경 요약 |

가능한 연구 질문 예시는 검사 수치가 비슷해도 일상 불편이 다른 이유, 약물 변경 후 일상 증상 변화다. 구체적인 설문 도구와 분석 방법은 연구 프로토콜에서 확정한다.

## 3. 병원의 역할과 데이터 신뢰

병원은 데이터 판매자가 아니라 핵심 정보의 출처를 확인하는 역할을 맡는다. 모든 기록을 병원이 직접 검수하도록 설계하지 않는다.

참여자 기록 제공 → 시스템이 항목·날짜·출처 정리 → 병원/연구기관이 핵심 정보 확인 → 가명 연구 데이터 생성 → 승인된 목적 안에서 분석 → 완료한 기여 보상.

| 신뢰 구분 | 의미·예시 |
| --- | --- |
| 사용자 기록 | 증상, 수면, 복약 확인 |
| 기기 연결 기록 | 활동량, 심박수 등; 초기 필수 수집 범위는 아님 |
| 문서 확인 기록 | 업로드된 병원 문서를 검수 |
| 의료기관 연결 기록 | 병원·검사기관에서 직접 받은 자료 |
| 연구용 검체 기록 | 향후 승인된 연구에서 채취한 검체 |

확인은 절대적 정확성 보장이 아니라 어떤 기관에서 언제 어떤 방식으로 생성했는지 확인된다는 의미다.

## 4. LNS 보상

보상은 데이터 판매 대금 대신 연구 참여에 든 시간·불편·기여에 대한 보상으로 설명한다. 첫 파일럿의 **총 A$100 상당 LNS는 검토할 가설**이다.

| 활동 | 횟수·단가 | 합계 |
| --- | --- | ---: |
| 등록 및 기본 설문 | 1회 × A$10 | A$10 |
| 병원기록 연결 또는 검증 문서 제공 | 1회 × A$15 | A$15 |
| 주간 체크인 | 12회 × A$4 | A$48 |
| 월간 설문 | 3회 × A$5 | A$15 |
| 최종 설문 | 1회 × A$12 | A$12 |
| 총계 | | **A$100** |

- 질병이 심할수록 더 보상하지 않는다. 민감도나 진단명을 가격으로 매기지 않는다.
- 중도 철회해도 완료한 활동의 보상은 유지한다.
- 호주 달러 기준 금액을 표시하고 지급 시점에 LNS 수량을 계산한다.
- 연구윤리위원회가 보상 구조를 검토한다.
- 추천인 모집, 코인 가격 맞히기 등 투기성 기능은 제외한다.

환산 시세 출처·시점, 수수료, 보관·출금·복구, 정산 예외 처리 방식은 아직 미정이다.

## 5. 앱 경험과 브랜드

차분하고 친근한 연구 도우미: 친근한 동반자 70%, 믿을 수 있는 연구 코디네이터 30%. 쉬운 표현, 한 화면에 한 가지 행동, 넉넉한 여백과 둥근 카드를 사용한다. 겁을 주거나 참여를 재촉하지 않는다.

| 용도 | 색상 |
| --- | --- |
| 따뜻한 아이보리 | `#F7F7F2` |
| 바다빛 초록 | `#2E8B7D` |
| 부드러운 코랄 | `#FF8A72` |
| 진한 차콜 | `#25323A` |

네온색, 코인 차트, 복잡한 지갑 주소, 차가운 병원 분위기는 피한다. 이메일·패스키 가입을 지향하고 지갑은 보상 안에 둔다. 초기 경험에 시드 문구나 가스비를 전면 노출하지 않는다.

| 하단 메뉴 | 역할 |
| --- | --- |
| 오늘 | 지금 할 일 |
| 연구 | 참여 가능 연구와 진행 상태 |
| 내 이야기 | 증상과 치료 변화 |
| 보상 | 적립·검증·지급 상태와 지갑 |

문구 참고(실제 제품은 영어 우선이며 번역은 별도 확정):

- “이번 주 체크인은 약 1분이면 끝나요.”
- “병원 기록이 안전하게 연결됐어요.”
- “참여할 수 있는 연구인지 확인하고 있어요.”
- “마음이 바뀌면 언제든 참여를 멈출 수 있어요.”
- “그동안 완료한 활동의 보상은 그대로 유지돼요.”
- “내 기록이 어떤 연구에 쓰였는지 확인해 보세요.”

## 6. 목표 기술 구성과 정보 분리

알파 목표: React Native iOS·Android, 하나의 모듈형 백엔드, FHIR R4 의료데이터 구조, My Health Record 테스트 연동, 병원 문서 업로드·운영자 검수, 주간 설문, 동의·철회·사용내역 기록, 패스키 기반 지갑, 내부 보상 장부, Solana 테스트넷 지급, 연구 운영자 웹 관리자.

| 정보 영역 | 보관·제공 원칙 |
| --- | --- |
| 신원 정보 | 별도 보관 |
| 의료 정보 | 호주 리전 암호화 저장 |
| 연구 정보 | 가명 ID로 제공 |
| 보상 정보 | 금액·상태·거래 기록 |

블록체인에는 건강정보, 진단명, 연구명, 이름, 지갑과 신원의 연결관계를 기록하지 않는다. LNS 지급 거래와 필요한 경우 위변조 확인용 묶음 증명값만 기록한다.

## 7. 단계별 로드맵

원문상의 상대 일정이며 프로젝트 시작일에 따른 실제 날짜는 미정이다.

| 단계 | 시기 | 작업 및 통과 조건 |
| --- | --- | --- |
| 0. 사업·규제 가능성 | 1~6주 | 호주 의료·연구·토큰 법률 검토, 윤리위원회 사전상담, 멜버른 IBD 병원/연구기관 1곳 및 바이오텍/CRO 설계 파트너 1곳 확보, 지급·보관 검토, 환자 12~15명 인터뷰, 프로토콜·데이터 항목 초안. 중대한 지급 법적 장애 없음, 기관의 확인 역할 동의, 구매 고객 관심, 최소 10명 참여 의향·이해도가 통과 조건 |
| 1. 클릭형 프로토타입 | 7~12주 | 실제 데이터 미저장. 온보딩, 연구 소개, 쉬운 동의, 적합성, 기록 연결/업로드, 주간 체크, 보상, 철회, 결과 요약. 15~20명에게 독립적 완료, 보상 이해, 의료정보 온체인 저장 오해 여부, 철회 접근성 검증 |
| 2. 모바일 알파 | 4~6개월차 | 위 기술 구성 구현, 정보 4영역 분리, 테스트 연동·테스트넷 지급 |
| 3. 비공개 베타 | 7~8개월차 | 20~30명, 개인정보 영향평가, 외부 보안·침투테스트, 지갑 분실/복구, 철회 후 데이터 처리, 장부/온체인 대조, 병원 업무시간 측정, 연구윤리 승인 완료 |
| 4. 첫 실제 연구 | 9~12개월차 | 30명 소프트 론칭 후 총 100명, 12주 체크인, 승인된 사람만 실제 병원기록 연결, 메인넷 단계 지급, 매주 품질·이탈·보상 오류 검토, 쉬운 결과 제공 |
| 5. 상용 버전 | 13~15개월차 | 두 번째 기관·동일 질환의 두 번째 유료 연구, 연구자 품질 대시보드, 크론병 확장, 웨어러블 1종, 선택적 재택 대변검체 30명 테스트, 기여 결과 제공 |
| 6. 글로벌 확장 | 16~24개월차 | 호주 두 번째 지역 → 뉴질랜드 → LNS 보상·출금 해결 후 미국 → 별도 EU 저장구조 확보 후 유럽 |

검체 기능은 MVP 안정화 후 물류·검사실·동의·보관기간을 정해 추가한다. 글로벌 확장 시 국가별 의료데이터는 해당 지역에 저장하고 글로벌 연구자에게는 승인된 가명 연구 데이터만 제공한다.

### 첫 실제 연구 목표

| 지표 | 목표 |
| --- | ---: |
| 12주 유지율 | 65% 이상 |
| 주간 체크인 완료율 | 75% 이상 |
| 연구에 사용 가능한 데이터 | 85% 이상 |
| 병원기록 확인 완료율 | 60% 이상 |
| 동의 내용 이해도 | 85% 이상 |
| LNS 지급 정산 일치율 | 100% |
| 중대한 보안·개인정보 사고 | 0건 |

검증된 참여자-주의 인정 요건, 각 비율의 분모·측정 시점·누락 및 철회 처리 방식은 원문에 없으므로 프로토콜에서 정의해야 한다.

## 8. 첫해 제외 범위

여러 국가 동시 출시, 여러 질환 동시 모집, 의료 상담 챗봇, AI 자동 진단, 유전체 원시데이터, MRI·CT 원본, NFT·스테이킹·DAO, 앱 내 코인 매매·LBank 직접 연결, 코인 시세 중심 화면, 사용자 순위·리더보드, 연구자 셀프서비스 마켓플레이스, 병원별 개별 연동 다수.

## 9. 현재 저장소와의 관계

- 현재 앱은 Expo/React Native 기반 **LNS Pulse 모션 PoC**다. Pulse → Trace → Seal, 72시간 기록, `+12 LNS`는 합성 예시이며 첫 UC 연구의 확정 프로토콜·보상 규칙이 아니다.
- 이번 정리는 문서 반영이다. 현재 화면·테마·런타임 기능을 이 기준으로 변경한 것은 아니다.
- [기존 개발 계획](../../plan/CODEX_DEVELOPMENT_PLAN.md)의 L2N 명칭, 코드 없는 신규 프로젝트 전제, RWA·투자 포트폴리오 등 넓은 범위는 과거 기획으로 참고한다. 새 제품 범위는 이 문서를 먼저 따른다.
- [Pulse 모션 명세](lns-pulse-motion-spec.md)는 해당 PoC의 세부 참고다. 모션 명세만으로 72시간 미션·웨어러블·예시 보상을 UC MVP 요구사항으로 확대하지 않는다.
- [모바일 기술 ADR](../architecture/adr-0001-mobile-motion-stack.md)와 [기존 QA 문서](../quality/pulse-accessibility-privacy-qa.md)는 각 기술·검증 맥락에서 참고한다.

## 10. 미확정 및 확인할 사항

- 최종 브랜드명, 연구 프로토콜, 포함·제외 기준, 동의 항목, 설문 도구·라이선스, 데이터 사전
