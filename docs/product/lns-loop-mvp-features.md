# LNS Loop 초기 앱 기능 정리

기준: 2026-09-11 후속 사용자 지시. **온보딩은 추후, Google 로그인, 활동 포인트 적립**을 현재 방향으로 삼는다. 이 문서는 기능 기획이며 구현 완료 명세가 아니다.

## 확정 방향과 제안의 구분

사용자 결정: 소개용 온보딩 보류, Google 로그인 제공, 초기에는 포인트 적립만 제공.

초기 제안(하단 4개 탭)은 아래 최신 화면 구성으로 대체되었다. 현재 구성은 Google 로그인, 프로젝트 소개 Index, 연구 설명·동의·적합성 확인, 포인트 지급·총점·랭킹, 마이페이지다. 기존 호주 성인 UC 연구 방향은 유지한다.

초기에는 지갑 생성·연결·주소 입력, 코인 잔액, 송금·출금·교환, 온체인 지급 기능이 필요하지 않다. 포인트와 LNS 수량을 같은 값으로 표시하지 않는다. 화면·알림·도움말에는 에어드랍, 토큰 전환, 향후 배분을 예고하는 문구를 넣지 않는다. Google 로그인은 계정 인증이며 의료정보 수집 동의나 연구 참여 동의를 대신하지 않는다.

## 기본 흐름

Google 로그인 → 프로젝트 소개 Index → 연구 설명 → 동의 → 적합성 확인 → 연구 참여 → 정해진 기록/설문 제출 → 확인 후 포인트 적립 → 내 기록·적립 내역 확인.

소개 슬라이드 없이 홈으로 진입한다. 거주 지역·성인 여부·질환 등은 해당 연구 신청 시 필요한 만큼 확인한다. Google 프로필만으로 연구 적합성이 검증되었다고 표시하지 않는다.

## 화면과 기능

| 화면 | 첫 구현 범위 | 주요 상태 |
| --- | --- | --- |
| Google 로그인 | 로그인 버튼, 첫 로그인 시 계정 생성, 세션 유지, 약관·개인정보 안내 링크 | 진행 중·취소·실패·재시도·세션 만료 |
| 홈 | 참여 중인 연구, 이번 주 할 일, 연구 진행률, 확정 포인트 요약, 다음 기록 버튼 | 첫 방문·참여 연구 없음·할 일 있음·완료·로딩 실패 |
| 연구 | 연구 목록·상세, 목적·대상·기간·활동·데이터 범위·적립 조건 안내, 참여 신청 | 모집 중·신청 검토 중·참여 중·종료·부적합 |
| 연구 동의·관리 | 필요한 기본정보, 적합성 확인, 항목별 동의, 동의 사본, 참여 철회 | 미동의·동의 완료·철회 완료 |
| 기록하기 | 주간 증상 체크, 복약 확인, 월간 생활 설문, 임시 저장·제출 | 미작성·작성 중·제출 중·실패·제출 완료·확인 중 |
| 내 기록 | 기록 목록·날짜별 상세, 증상·복약 추이, 연결 자료·출처·확인 상태 | 기록 없음·사용자 입력·문서 검토 중·확인 완료·보완 요청 |
| 의료자료 제공 | 문서 업로드, 필요한 자료 안내, 업로드 결과·검토 상태 | 업로드 중·실패·검토 중·확인·재제출 요청 |
| 포인트 | 확정 총점, 확인 중 점수, 활동별 적립 내역, 적립 규칙 | 확인 중·적립 완료·보류·조정 |
| 프로필·설정 | 기본정보, 알림 설정, 동의 관리, 도움말·문의, 로그아웃, 계정 삭제 요청 | 저장 실패·요청 접수·완료 |
| 알림 | 기록 일정, 검토 결과·보완 요청, 포인트 적립 알림 | 읽음·미읽음; 푸시는 기본 화면 이후 연결 가능 |

주간 증상 항목은 원래 기획의 배변 횟수·혈변·긴급성·복통·피로·복약·일상 영향에서 연구 프로토콜에 맞게 확정한다. 이 문서가 임상적으로 검증된 설문 도구를 지정하는 것은 아니다.

## 홈의 정보 순서 제안

1. 이번 주 할 일: 가장 중요한 다음 행동 하나
2. 참여 중인 연구: 연구명, 현재 주차, 다음 일정
3. 내 기여: 완료한 기록 횟수와 확정 포인트
4. 최근 기록: 마지막 기록과 확인 상태
5. 연구 미참여 시: 첫 연구 소개와 참여 조건 확인 버튼

포인트는 참여 결과로 보여준다. 기존 캡슐 그래픽과 72시간 카운트다운을 메인 화면의 중심으로 유지할 필요는 없다.

## 포인트 적립 설계 제안

| 활동 | 적립 방식 제안 |
| --- | --- |
| 연구 기본 설문 | 연구당 최초 유효 제출 1회 |
| 의료자료 제공 | 정해진 필수 자료 확인 완료 후; 같은 문서 재업로드는 중복 적립하지 않음 |
| 주간 체크인 | 연구의 주차별 유효 제출 1회 |
| 월간 설문 | 지정된 설문 회차별 1회 |
| 최종 설문 | 연구당 완료 1회 |

구체적인 점수는 아직 정하지 않는다. 단순 로그인·연속 출석·친구 추천은 초기 적립 항목으로 제안하지 않는다. 질병의 심각성이나 응답 내용을 기준으로 점수를 높이지 않는다. 완료되어 확정된 정상 기여 포인트는 연구 철회만으로 회수하지 않는다.

UI에서는 확정 포인트와 확인 중 포인트를 분리한다. 실패 후 재시도, 중복 클릭, 기록 수정으로 이중 적립되지 않도록 서버가 적립 여부를 판정한다. 적립 취소·조정은 기존 거래를 조용히 덮어쓰기보다 이유가 남는 별도 내역으로 관리한다.

포인트 안내 문구 초안: “연구 활동을 완료하고 포인트를 모아보세요.” 사용자에게는 적립 조건·점수·상태·이력만 설명한다. 에어드랍 안내, 예정 배너, 청구 버튼, 토큰 환산이나 미래 보상 예고는 표시하지 않는다.

## 운영에 필요한 최소 기능

- 연구·설문·회차·적립 조건 등록 및 버전 관리
- 참여 신청과 적합성 확인, 문서 검수·보완 요청
- 제출·확인·적립 상태 조회, 중복 적립 방지
- 포인트 조정 사유·담당자·시각과 변경 이력
- 동의·철회·삭제 요청 처리 및 문의 관리
- 포인트 정산 확인을 위한 계정별 확정 점수와 적용 규칙 버전 조회

포인트 원장에는 계정 ID, 연구/활동 ID, 회차, 금액(점수), 상태, 이벤트 ID, 규칙 버전, 시각, 조정 사유를 남기는 것을 제안한다. 정산용 내보내기는 내부 계정 ID와 필요한 점수만 포함하도록 설계한다. 의료정보를 포인트 정산 파일에 넣지 않는다. 지갑 연결은 현재 구현 범위에 포함하지 않는다.

## 구현 순서

1. **앱 기본 구조:** Google 로그인, 세션, 홈·연구·내 기록·포인트 탭, 설정. 실제 인증과 화면용 데모 계정을 구분한다.
2. **첫 연구 흐름:** 연구 상세·신청·필요 정보·동의, 주간 기록과 제출, 내 기록 상세.
3. **포인트 흐름:** 활동별 적립 조건, 서버 원장, 확인 중·확정 상태, 이력, 재시도/중복 방지.
4. **운영 연결:** 문서 업로드·검토, 월간·최종 설문, 알림, 철회·삭제 요청, 운영자 관리.

데모 화면 작업은 1~3 순서로 진행할 수 있다. 실제 연구 참여를 받는 버전은 필요한 동의·철회·자료 검토·포인트 서버 관리까지 연결되어야 한다.

## 뒤로 미룰 항목

소개 온보딩, 지갑, 토큰 지급·에어드랍 청구, 코인 시세·교환·출금, 웨어러블, 검체 수집, 연구자 셀프서비스, 추천 보상, 고급 AI 분석. 실제 병원 자동 연결은 기관 조건 확인 후 연결하고 초기에는 문서 제공·검수 경로를 우선 제안한다.

## 기존 문서와의 관계

이 문서가 기존 제품 기준안의 가입·초기 보상 구현 범위보다 우선한다. 기존 A$100 LNS 표는 과거 가설이며 초기 포인트의 환산표가 아니다. 패스키 지갑·Solana 테스트넷·메인넷 지급·지갑 복구는 이번 구현 범위에서 뒤로 이동한다. 지역·질환·연구 기간·기여 중심 원칙은 유지한다.

## 최신 화면 구성 — 사용자 지정안

이 절은 앞서 제안한 홈·연구·내 기록·포인트 4탭 구성보다 우선한다. 화면 목록을 확정하는 것이며 하단 탭 배치는 아직 정하지 않았다.

| 영역 | 구성 |
| --- | --- |
| Google 로그인 | Google 가입·로그인과 세션 유지 |
| LNS 프로젝트 소개 Index | 프로젝트 목적, 참여 방식, 연구 기여와 포인트 설명, 연구로 이동 |
| 연구 참여 | 연구 설명 → 동의 → 적합성 확인 → 적합한 참여자의 연구 활동 |
| 포인트 지급 | 유효한 활동 완료·확인 후 포인트 적립 및 결과 안내 |
| 총 포인트·랭킹 | 확정 누적 점수, 적립 내역, 참여자 포인트 순위 |
| 마이페이지 | 프로필, 참여 연구·진행 상태, 동의·철회, 알림·계정 설정 |

기존의 별도 '내 기록' 탭은 필수 구성이 아니다. 필요한 기록·제출 내역은 연구 상세 또는 마이페이지 안에 배치하는 것을 제안한다. Index는 프로젝트를 소개하는 기본 화면이며, 보류한 순차적 소개 온보딩과 구분한다.

랭킹은 이번 사용자 지시로 초기 범위에 추가되었다. 앞선 문서의 사용자 순위·리더보드 제외 방침은 이 항목에 한해 변경한다. 순위 기준은 확정 포인트를 제안하며, 공개 표시는 닉네임·포인트로 구성하고 질환·증상·의료기록은 표시하지 않는다. 전체/기간별 순위, 동점 처리, 공개 참여 방식은 상세 설계에서 정한다.

포인트 지급은 앱 내부 포인트 적립을 뜻한다. 사용자 화면에는 에어드랍·토큰 전환·향후 배분 안내를 넣지 않는다. 연구 적합성이 맞지 않거나 확인 중인 경우의 안내도 연구 참여 흐름에 포함한다.
